# 2. Slot Generation Strategy

The spec says:

> Return the next N available slots

But it does **not define how slots are generated inside a valid gap**.

Example gap:

```
10:00 — 11:00
Meeting duration = 30 minutes
```

Possible interpretations:

Option A — **single slot per gap**

```
10:00–10:30
```

Option B — **multiple sequential slots**

```
10:00–10:30
10:30–11:00
```

Option C — **sliding window**

```
10:00–10:30
10:01–10:31
10:02–10:32
...
```

Most scheduling systems use **Option B**, but the spec does not say.

**Clarification needed**

* Are slots sequential blocks?
* Should multiple slots be generated per gap?
